# 汽车设计文案助手｜创作链路与交互重构 PRD V2

> 交互主链路已由 [现行 PRD](../prd.md) 接管。本文仅作历史对照。


## 1. 文档信息

- 产品：Vehicle Design Writer / 汽车设计文案助手
- 版本：V2.0
- 状态：实施基线
- 目标：把“风格采集”和“汽车设计文案创作”从功能堆叠改造成有证据依赖、可回退、可解释的串行工作流
- 核心原则：先建立视觉证据，再形成 PFDBI 判断，最后才允许生成和风格化文案

## 2. 背景与问题

### 2.1 风格库

当前新增风格拆成“保存档案 → 选择文件夹 → 提取 Style DNA”三个并排模块。数据库外键要求文档必须归属一个风格，因此前端把“选择文件夹”直接依赖 `styleId`，导致用户必须先理解并执行一次技术性的“保存档案”动作。

主要问题：

1. 用户目标是“用一批历史文案创建风格”，不是先创建一个空档案。
2. 三栏并排不能表达先后关系和当前状态。
3. 取消选文件夹后可能留下无内容档案。
4. 风格列表没有删除入口，虽然底层已有删除能力。
5. 提取失败、样本不足、文件解析失败时缺少明确恢复路径。

### 2.2 工作台

当前“按工作流生成”一次性执行视觉观察、PFDBI、Base Draft、模板匹配、Style Adapter 和质检。用户无法确认每个中间产物，也无法理解为什么某个阶段尚不可用。

主要问题：

1. 新建项目页过早要求平台、类型、时长、风格和草稿，视觉证据反而变成可选项。
2. 没有图片时仍可运行 PFDBI，与产品“视觉证据优先”的定位冲突。
3. 视觉观察和 PFDBI 被隐藏在一次生成任务中，无法单独重跑或确认。
4. “添加矩形标注”使用固定坐标加系统 `prompt`，没有可视化框选，用户无法知道标注区域。
5. 图片没有“主分析车型 / 其他车型”角色，模型无法按用户声明的关系做比较。
6. 修改图片或标注后，旧 PFDBI 和稿件可能继续存在，存在证据污染。
7. 顶部阶段只是可点击标签，没有完成、可执行和锁定状态。

### 2.3 Electron 窗口

Windows 使用默认原生标题栏，标题栏保持系统浅色，而应用内容为深色，形成明显割裂。

## 3. 产品目标

### 3.1 用户目标

1. 用户可以在一个连续流程中创建风格、导入样本并提取 Style DNA。
2. 用户可以删除误建或不再使用的风格，并清楚知道关联影响。
3. 用户上传车型图片后，可以预览、分类、画出一个或多个矩形区域并写分析意图。
4. 用户必须先完成视觉观察，才能运行 PFDBI。
5. PFDBI 能区分主体评价，以及用户声明关系下的其他车型比较。
6. 用户确认 PFDBI 中间产物后，再补充选题参数、初步草稿、平台、类型、时长和风格，生成最终稿。
7. 整个 Electron 窗口保持统一深色。

### 3.2 业务目标

1. 降低空风格档案和无证据 PFDBI 的产生概率。
2. 让每份最终稿都可以追溯到图片、标注、视觉观察和 PFDBI。
3. 上游数据变化时自动使下游结果失效，保证结果一致性。
4. 保留 Demo Mode，使无 API Key 时仍可完整体验状态流。

## 4. 非目标

1. 本期不实现自由多边形、曲线或语义分割标注。
2. 本期不实现联网抓取车型参数或自动验证车型年份。
3. 本期不实现多人协作、云端同步和权限体系。
4. 本期不做像素级车型图片配准。
5. PFDBI 不输出伪精确的总分或排行榜；重点是证据、判断和比较维度。

## 6. 端到端主链路

### 6.1 风格创建链路

`填写名称/平台/类别 → 选择文案文件夹 → 系统创建风格并导入 → 核对样本 → 提取 Style DNA → 进入详情`

交互规则：

1. “选择文案文件夹并继续”是第一主按钮。
2. 点击后先打开系统目录选择器；用户取消时不创建任何档案。
3. 选择成功后，主进程创建风格，再把解析结果写入该风格。
4. 至少一篇解析成功后，开放“提取 Style DNA”。
5. 解析失败文件逐条展示错误，但不阻断其他成功文件。
6. 提取失败后保留档案和样本，允许重试。
7. 用户离开已导入但未提取的风格时，风格列表显示“待提取”。

### 6.2 文案创作链路

`创建选题 → 上传参考图 → 设置图片角色 → 矩形标注 → 运行视觉观察 → 配置比较关系 → 运行 PFDBI → 填写成稿参数/初稿 → 生成 Base Draft → 模板匹配与 Style Adapter → 质检 → 编辑/导出`

严格门禁：

1. 项目至少有一张“主分析车型”图片，才可运行视觉观察。
2. 每张参与分析的图片都完成视觉观察，才可运行 PFDBI。
3. PFDBI 成功后，才开放成稿设置和生成按钮。
4. 生成文案所需参数：选题非空、平台、内容类型、目标时长、Style DNA 可选。
5. 最终稿生成后，才开放局部重写、版本恢复与导出。

## 7. 工作流状态机

### 7.1 状态定义

- `images_pending`：项目已创建，尚无主分析图片
- `annotation_ready`：已有图片，可继续分类和标注
- `vision_ready`：所有当前图片均存在最新视觉观察
- `pfdbi_ready`：存在与当前视觉观察及比较配置对应的 PFDBI
- `brief_ready`：PFDBI 已完成，成稿参数有效
- `generating`：正在生成 Base Draft / 风格化稿 / 质检
- `ready`：最终稿可编辑、重写和导出

### 7.2 失效规则

以下动作必须清除受影响的下游产物：

- 新增/删除图片：清除 PFDBI、Base Draft、模板匹配、最终稿、质检；新增图片尚未观察，因此视觉阶段变为未完成。
- 修改图片角色、车型标签或比较备注：清除该项目 PFDBI 及全部稿件。
- 新增/修改/删除标注：清除对应图片视觉观察、PFDBI 及全部稿件。
- 修改选题或初步草稿：保留图片和视觉观察，清除 PFDBI 及全部稿件。
- 修改平台、类型、时长、风格或商业参数：保留视觉观察和 PFDBI，清除 Base Draft 及后续稿件。

### 7.3 阶段导航表现

每个阶段显示一种状态：

- 已完成：可进入查看或重跑。
- 当前：高亮并展示主要操作。
- 可执行：可进入，提示下一步。
- 已锁定：不可进入，悬停或说明文字展示缺失条件。

不允许用户通过顶部阶段导航绕过门禁。

## 8. 图片与标注

### 8.1 图片角色

每张图片必须具有角色，但不限制数量：

- `primary`：主分析车型，允许 0 张或多张。
- `other`：其他车型，允许 0 张或多张。它与主分析车型的关系写在比较说明中，不再预设“同系不同代”或“同代不同系”。

每张图片可填写：

- 车型标签：例如“宝马 3 系 G20 LCI”
- 比较说明：例如“上一代同系”“同级对标”“概念车参考”
- 角色

### 8.2 矩形标注编辑器

1. 点击图片或“添加标注”打开大图弹层。
2. 在图片显示区域按下并拖动，实时绘制矩形。
3. 坐标保存为相对图片的 `0–1` 值，不受窗口缩放影响。
4. 完成框选后填写备注：
   - 重点分析
   - 对比差异
   - 不要作为判断依据
   - 自定义说明
5. 一张图片允许多个矩形。
6. 已保存矩形以编号覆盖显示，并在侧栏列出备注。
7. 支持删除已有标注。
8. 宽或高低于图片显示区域 2% 的框视为误操作，不保存。

### 8.3 视觉模型输入

每张图片的视觉请求包含：

- 原图
- 图片角色
- 车型标签（声明为用户提供，不视为模型确认）
- 比较说明
- 所有矩形的相对坐标和备注

视觉模型只输出观察事实和不确定性，不直接输出最终审美结论。

## 9. PFDBI 与对比评价

### 9.1 主体评价

对主分析车型按 P / F / D / B / I 输出：

- 观察
- 证据
- 解释
- 审美效果
- 判断
- 是否有足够证据

### 9.2 其他车型比较

适用于 `other` 图片，关系以用户填写的比较说明为准，回答：

- 这张图与主分析车型是什么关系
- 能观察到哪些相同或相近之处
- 比例、形体、细节上的关键差异
- 哪些结论只能视为推断

没有 `other` 图片时，不生成伪比较结论，界面显示“未提供其他车型参考图，或比较说明不足”。旧数据中的纵向/横向比较仅作兼容展示。

### 9.3 证据约束

1. 模型不得把用户填写的车型标签当成已验证事实。
2. 结论必须引用视觉观察或标注区域。
3. 证据不足的维度必须 `applicable=false`。
4. facts / inferences / personalPreferences 必须分栏。
5. 比较关系只在对应角色图片存在时输出。

## 10. 成稿设置与生成

PFDBI 完成后展示成稿设置：

- 选题
- 初步草稿（可空）
- 平台
- 内容类型：车型解读 / 设计知识 / 设计观点 / 设计回顾 / 新车热点 / 设计跨界（与风格库类别共用）
- 目标时长
- 风格模板（可空；空时保持 Base Draft 的中性表达）
- 商业合作参数

生成顺序不可合并：

1. Base Draft：只使用选题、初稿、视觉观察、PFDBI、平台和时长，先保证内容逻辑。
2. Template Match：根据选题和内容类型选择结构模板。
3. Style Adapter：只改变组织和表达，不改变事实及 PFDBI 结论。
4. Quality：检查时长、证据覆盖、风格一致性、事实风险和 AI 腔。

## 11. 风格删除

### 11.1 入口

- 风格列表卡片右侧提供删除图标。
- 风格详情提供“删除风格”次级危险操作。

### 11.2 确认

弹层必须说明：

- 将删除历史文案、Style DNA、结构模板和 Few-shot。
- 已有项目不会被删除。
- 已有项目对该风格的引用会被解除或在生成时回退到无风格模式。
- 操作不可撤销。

Demo 风格允许删除；如应用需要演示数据，可在后续重新初始化，不在本期阻止删除。

## 12. Electron 深色窗口

Windows 主窗口使用隐藏标题栏并启用 `titleBarOverlay`：

- 标题栏背景：与应用顶栏一致的深色。
- 窗口控制按钮符号：浅色。
- BrowserWindow `backgroundColor`：应用最深背景色，避免启动闪白。
- 页面顶部预留覆盖层高度。
- 可点击按钮、输入框和导航声明为 `no-drag`，其余顶部区域允许拖动窗口。

macOS 和 Linux 保持平台安全默认行为，只设置启动背景色。

## 13. 数据模型

### 13.1 reference_images 扩展

- `role`: `primary | other`
- `vehicle_label`: 用户输入的车型标签
- `comparison_note`: 与主分析车型的关系说明

### 13.2 PFDBI 扩展

保留原有 P/F/D/B/I，并增加可选结构：

- `peerComparisons[]`
  - subjects
  - relation
  - observations
  - differences
  - evidence
- `verticalComparisons[]` / `horizontalComparisons[]`：仅兼容旧 JSON，新分析不再写入

旧数据缺少新字段时按空数组兼容。历史 `vertical` / `horizontal` 角色启动时迁移为 `other`。

## 14. IPC 设计

风格：

- `styles.createFromFolder(input)`：选择目录成功后创建并导入，取消时返回 null。
- `styles.remove(id)`：删除风格及关联数据。

项目：

- `projects.updateImage(id, metadata)`
- `projects.removeAnnotation(id)`
- `projects.analyzeVision(projectId)`
- `projects.analyzePfdbi(projectId)`
- `projects.generate(projectId)`：只执行 Base Draft 到质检；若 PFDBI 不存在则拒绝。

所有主进程 handler 都必须再次校验门禁，不能只依赖按钮禁用。

## 15. 异常与反馈

- 无图片运行视觉观察：`请先上传至少一张参考图`
- 尚有图片未观察就运行 PFDBI：`请先完成全部参考图的视觉观察`
- 无 PFDBI 生成文案：`请先完成 PFDBI 评价`
- 无成功文档提取风格：`至少需要 1 篇解析成功的文案`
- API 失败：保留已完成中间产物，显示可重试按钮，不自动跳到下一阶段。
- 进行中：禁用会改变上游数据的操作，避免竞态。

## 16. 验收标准

### 16.1 风格库

- 用户不需要手动执行“保存档案”即可完成导入。
- 取消目录选择不会新增风格。
- 至少一篇成功文档后可提取 Style DNA。
- 列表可删除风格，确认后卡片立即消失。
- 删除后刷新应用，风格不再出现。

### 16.2 图片与标注

- 上传后立即显示本地预览。
- 点击添加标注会打开可视化编辑器。
- 拖动可见矩形，保存后刷新仍存在。
- 可删除标注。
- 修改标注后，该图片旧视觉观察和项目下游产物失效。

### 16.3 串行流程

- 无图时视觉观察、PFDBI 和生成均不可运行。
- 图片未全部观察时 PFDBI 不可运行。
- PFDBI 未完成时成稿设置和生成不可运行。
- PFDBI 完成后可以配置平台、类型、时长、风格和初稿。
- 最终稿生成后可以编辑、保存版本、局部重写和导出。

### 16.4 对比评价

- 纵向图片进入纵向比较上下文。
- 横向图片进入横向比较上下文。
- 缺少某类图片时明确显示未提供，不生成虚假比较。

### 16.5 窗口

- Windows 顶部不再出现白色系统标题栏。
- 最大化、最小化、关闭可用。
- 顶部拖拽和双击最大化可用。
- 启动过程无明显白色闪屏。

## 17. 测试策略

### 17.1 单元测试

- PFDBI 新旧数据 schema 兼容。
- 图片角色校验。
- 工作流阶段计算和门禁。
- 上游变更对应的下游失效范围。
- 坐标归一化与最小矩形过滤。

### 17.2 集成测试

- 风格创建并导入的取消、成功、部分解析失败。
- 图片元数据更新与标注增删。
- 无图运行视觉观察被拒绝。
- 未完成视觉观察运行 PFDBI 被拒绝。
- 无 PFDBI 生成文案被拒绝。

### 17.3 端到端验证

1. 启动 Electron。
2. 新增风格并导入样本文档，提取 Style DNA。
3. 删除测试风格。
4. 新建选题，进入工作台时默认停在“参考图与标注”。
5. 上传参考图，按主分析车型 / 其他车型分类，并填写比较说明。
6. 在图片上拖出矩形并保存备注。
7. 运行视觉观察，确认每张图片出现结果。
8. 运行 PFDBI，确认主体评价与其他车型比较。
9. 配置平台、类型、时长、风格和初稿。
10. 生成并检查 Base Draft、最终稿、质检、版本和导出。
11. 修改一个标注，确认视觉观察、PFDBI 和稿件回到待运行状态。
12. 检查 Windows 深色标题栏、拖动和窗口控制按钮。
