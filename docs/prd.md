# 汽车设计文案助手｜工作台 PRD

## 1. 文档信息

- 产品：Vehicle Design Writer / 汽车设计文案助手
- 版本：V4.0
- 状态：现行规格
- 取代关系：交互与主链路以本文为准。需求变更见 [ChangeLog.md](./ChangeLog.md)。旧的风格配置双链路与 V2 串行工作台见 [archive](./archive/README.md)。
- 目标：让人在工作台把一期文案写完——先想清楚讲什么，再对照车图写下设计判断，最后自己写初稿。风格靠一篇篇成稿积累，不再单独维护风格库。

## 2. 为什么要改

上一版把产品拆成「风格配置」和「文案创作」两条链路，生成初稿前还要选手动风格卡或让 Agent 选卡。实际写稿时：

1. **风格库过早**：还没写出几篇自己的口播，就先抽别人的风格卡，用不上。
2. **准备上下文挤在一页**：选题、传图、框选、跑视觉观察、跑 PFDBI、再生成，步骤重、人也被模型带着走。
3. **框选和自动分析不是现在需要的**：当期更需要的是图库对照、人眼写下 PFDBI，以及一块能检查字数的初稿编辑区。

V4 不放弃 V3 的核心原则：**视觉证据与 PFDBI 判断仍由人确认；事实补充只当素材，不是文风。** 改变的是入口：先写，不先建风格库。

## 3. 产品原则

1. **一条工作台链路**：一级菜单只有首页、文案工作台、设置。
2. **人写材料，人写初稿**：选题、事实、看图判断、正文都由人完成。
3. **风格后置**：多写几篇就是自己的文案风格；本期不提供风格库、不选手动风格标签。
4. **事实补充是素材，不是文风**：参数、原话、报道只用于“讲什么”。
5. **PFDBI 由人眼写**：对照看图后按五维填写，模型不代替下审美结论。
6. **字数跟着口播走**：预期时长按每分钟 250 字估算目标字数。

## 4. 非目标

1. 不提供风格库、风格提取、选手动风格卡。
2. 不自动联网抓取车型参数、发布会或媒体报道。
3. 不做矩形框选标注。
4. 不做多人协作、云端同步。
5. 不让模型绕过 PFDBI 直接下审美结论。

## 5. 信息架构

```text
首页
设置

文案工作台
  ├─ 项目列表 / 新建文案 / 导入安装包
  └─ 打开项目（顶栏显示标题、保存状态灯；可保存 / 导出安装包）
       ├─ 选题想法
       ├─ 视觉素材
       ├─ 设计分析
       └─ 初稿文案
```

## 6. 文案创作

打开项目后，左侧从上到下四个二级标签。顺序建议如此，但不做阶段门禁，随时可切。

### 6.1 选题想法

人必须给出选题 / 核心问题。初步想法和事实补充可空。

| 字段 | 用途 |
| --- | --- |
| 选题 / 核心问题 | 这期要回答什么 |
| 初步想法 | 口播意向、已有观点，不是事实源 |
| 事实补充 | 参数、发布会原话、报道、设计历史；只当素材 |

### 6.2 视觉素材

当期文案的图库，不是分析画布。

- 上传图片
- 角色：主分析车型 / 其他车型
- 车型标签
- 比较说明（其他车型写清与主分析车型的关系）
- 不做框选标注

无图也可以先去做设计分析和写稿。

### 6.3 设计分析

- 两个图片对比预览区
- 每个预览区右上角切换本项目已导入的图片
- 滚轮缩放，左键按住拖移画面
- 下方按 PFDBI 标签（P 比例姿态 / F 型面 / D 细节 / B 品牌 / I 创新）切换，在文本框写下人眼观察
- 尽量分开事实、推断和判断；不自动跑视觉观察或 PFDBI 模型

### 6.4 初稿文案

只负责正文和辅助检查：

- 左侧：初稿文本框；左下角显示当前字数
- 右侧上部：文案标题、内容类型（车型解读 / 设计知识 / 设计观点 / 设计回顾 / 新车热点 / 设计跨界）、预期时长（分钟）
- 目标字数 = 分钟 × 250

### 6.5 保存、导入与导出

文案项目以安装目录 `data/projects` 为库（设置可改自定义路径，恢复默认则继续跟当前安装目录走）。

- **新建**：选题和参考图先留在内存。顶栏状态为「未保存」。
- **保存**：在项目库按标题新建（或覆盖已有）文件夹，内含 `参考图/` 和一份 `项目.json`。状态变为「已保存」。改过未写回则为「未更新」。
- **导出**：把当前项目文件夹打成 zip 安装包，弹出另存为自选地址。尚未保存时会先保存再打包。
- **导入**：选择 zip 或旧版项目文件夹，复制进当前项目库。上一版多个 txt 仍可导入。

入口：工作台顶栏「保存」「导出安装包」；项目列表导入 / 导出。

## 7. 事实补充

项目级纯文本。典型内容：官方参数、发布会原话、报道摘录、设计历史。不是风格，也不是 PFDBI 替代物。与「初步想法」分开存放。修改后保留已写的 PFDBI 和初稿。

## 8. 数据要点

- `projects.topic` / `projects.title`：选题与展示标题
- `projects.draft`：初步想法
- `projects.facts`：事实补充
- `projects.contentType` / `projects.durationSeconds`：初稿辅助检查
- 参考图：上传时只进内存；保存项目时才写入该项目文件夹的 `参考图/`
- 项目库：默认安装目录 `data/projects`（设置可改；恢复默认不固化路径）
- 导入 / 导出：导出为 zip 安装包并自选地址；导入 zip 或旧文件夹到项目库。包内含 `参考图/` 和 `项目.json`。上一版多个 txt 仍可导入
- PFDBI：人写内容写入各维 `judgement`
- 初稿正文写入项目清单的 `script`

## 9. 验收

1. 侧栏和路由不再出现风格库；旧 `/styles` 地址回到工作台。
2. 打开项目后可见四个纵向标签，顶栏能切换项目。
3. 视觉素材页能上传、改角色和标签，没有框选标注入口。
4. 设计分析页能对照两张图，并按 PFDBI 标签手写保存。
5. 初稿页能改标题、内容类型、时长；正文左下角字数按每分钟 250 字对照。
6. 保存选题、事实、PFDBI 或正文时，其它已写内容仍在；顶栏能区分未保存 / 未更新 / 已保存。
7. 点保存后在 `data/projects` 看到项目文件夹；导出自选 zip 地址；导入 zip 或旧文件夹后能查看选题、参考图、PFDBI 和初稿。
